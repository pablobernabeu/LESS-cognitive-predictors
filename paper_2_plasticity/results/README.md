# `paper_2_plasticity/results` — what the manuscript reads

Every number in Paper 2 comes from a file in this folder. The manuscript reads them
through inline R and transcribes no statistic by hand, so re-rendering is what updates the
reported values.

## Naming

| Pattern | What it is |
|---------|------------|
| `_*.csv` | A machine-written summary table the manuscript reads. The leading underscore marks it as a manuscript-facing artefact and sorts the whole set together. |
| `p2_*.csv`, `p2_*.rds` | Model-level artefacts named after the model that produced them, chiefly the projpred solution paths and summaries. Step 8 and its recovery script write these. |
| `07_aperiodic_features.csv` | The one pipeline-internal table. Step 07 writes it and step 04 reads it, and the manuscript never touches it. It carries the number of the script that writes it precisely because it is not manuscript-facing, so leave the name alone: both scripts address it by that literal string. |
| `*.rds` | Fitted brms objects and their per-model summaries. **Not in version control** (`.gitignore` excludes `results/*.rds`), because they are large and are regenerated by the model scripts. Step 6 reads them to build the pooled CSVs. |

`_sample_flow.csv` and `_participants.csv` arrive from outside this folder's own pipeline.
**Paper 1's** step 0 writes them into both papers' `results/`, so that the two papers
cannot report different cohort numbers.

## What writes what

The pipeline table in [`../README.md`](../README.md#pipeline-scripts-run-in-order) maps
each stage to the files it produces, and is the authority. In outline, step 6 writes the
pooled convergence, posterior-summary, attainment and reliability tables from the fitted
`.rds`, and step 8 writes the projpred paths. Steps 9b and 9c write the two model
comparisons, `_aperiodic_loo_compare.csv` and `_aperiodic_kfold_compare.csv`. Steps 10 to
12 write the descriptives the manuscript injects and the descriptive figures read.

`_provenance.csv` is the exception in kind. It is written at fit time by
`../../_shared/R/04_provenance.R` whenever step 04 runs, and records the versions that run
actually loaded together with the seed. Where any other account of the environment
disagrees with it, it is right. Until step 04 has run against the current results, the
file is absent and the manuscript prints `pending` in its place.

## One comparison to read with care

There are two comparisons between the raw-band and de-confounded Part A reference models,
and they are not interchangeable. `_aperiodic_loo_compare.csv` is the pre-specified
PSIS-LOO on the common sample, and it is retained. It leaves out one trial at a time,
though, while the six predictors separating the two models are constant within a
participant, so it is close to blind to what is being compared.
`_aperiodic_kfold_compare.csv` leaves out whole participants, and that is the comparison
the Discussion rests on.

## Reproducing them

None of these files is produced at render time. Run the pipeline (see
[`../scripts/README.md`](../scripts/README.md) and [`../hpc/README.md`](../hpc/README.md)),
pull the CSVs back to the rendering box, and re-render.
